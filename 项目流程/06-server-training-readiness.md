# 2026-07-20 3090 服务器训练配置评估

## 背景和目的

当前 SO-101 项目已完成绿色、葡萄紫两种颜色、三种光照条件的数据采集和正式归档。本文核对当前数据、实际采集环境与 `JereoZero/so101-real` 训练流程，判断下一步是否适合租用 Ubuntu RTX 3090 服务器，并给出实例选择与启动训练前的验收条件。

## 当前项目状态

- 绿色：`16 + 15 + 14 = 45` 条，`10,007` 帧。
- 葡萄紫：`15 + 15 + 15 = 45` 条，`7,771` 帧。
- 合计：`90` 条、`17,778` 帧、两路相机、统一 `20 FPS`，正式归档约 `397 MB`。
- 六组数据均有连续 parquet、每条两路 MP4 和完整元数据；此前质检已排除短误录，末帧均完成放盘。
- 当前仍是六个独立原始 LeRobot 数据集，尚未建立两颜色合并训练集。
- 本机没有发现 `smolvla_base/model.safetensors`，尚未完成预训练模型准备和 normalizer migration。

## 服务器结论

### GPU

单卡 RTX 3090 24 GB 足以进行当前 SmolVLA 微调，且比本机 RTX 3060 Laptop 6 GB 更适合正式训练。当前任务没有必要使用多卡。RTX 4090 24 GB 也适合且更快，但不是必要条件；若 4090 小时价明显高于 3090，优先选 3090。

截图地址栏实际为 `RTX-4090` 页面，不是 3090 页面。

### 镜像

截图中选择的 `PyTorch 2.10.0 / Python 3.12 / CUDA 12.8` 不建议用于直接复现当前 repo 训练流程，因为当前源码要求 `torch<2.8.0`。

优先级：

1. `PyTorch 2.7.1 / Python 3.10 / CUDA 12.6`，与本机采集环境一致。
2. 若平台没有该组合，选择 Ubuntu 22.04 + Miniconda 基础镜像，再创建 Python 3.10 环境并安装当前源码。
3. 只有明确决定迁移到 LeRobot 0.5.1，并愿意先改命令和做兼容性验证时，才选择截图中的 PyTorch 2.10.0 镜像。

### CPU、内存和磁盘

- GPU：RTX 3090 24 GB，数量 `1`。
- CPU：至少 `8 vCPU`，建议 `16 vCPU`，用于双路视频解码和数据加载。
- 内存：至少 `32 GB`，建议 `64 GB`。
- 系统：Ubuntu 22.04。
- 计费：首次环境搭建和 smoke test 使用按量计费。
- 磁盘：默认 `60 GB` 只适合最小验证。建议额外增加 `100 GB`，总可用空间约 `160 GB`，用于 Conda 环境、预训练模型、多个 checkpoint 和导出结果。

## 训练前顺序

1. 将六个原始数据集合并为 `smolvla90_2color_v1`，保留绿色和葡萄紫两条语言任务，并验证 `90` 条、`17,778` 帧、双相机字段和随机 episode 可读取。
2. 在服务器准备当前 repo 和同版本环境，下载 `lerobot/smolvla_base`，执行 normalizer migration。
3. 先跑 `200-500` 步 smoke test，使用 `batch_size=8`；确认 GPU 被使用、loss 有限、无 OOM、能保存并重新加载 checkpoint。
4. 再依次测试 `batch_size=16/32/36`，以不 OOM 且显存利用稳定为准，不直接假设 24 GB 必须使用更大 batch。
5. 首轮正式训练先到 `10,000` 步，并保留中间 checkpoint。当前只有 90 条演示，不应未经实机验证直接照搬原项目 210 条数据的 40,000 步结论。
6. 下载多个 checkpoint 回本机做实机评估；每种颜色、每种光照至少 10 次，记录成功率、抓空、碰撞和放偏。根据结果决定是否继续到 20,000-40,000 步。

## 成功标准

- 合并数据集能由服务器端 LeRobot 静态加载，episode 数和帧数与本机一致。
- `200-500` 步 smoke test 无 NaN/Inf、OOM 或字段映射错误，并生成可重新加载的 checkpoint。
- 训练目录、环境锁定信息、日志和 checkpoint 在关机前同步回本机。
- 模型效果以本机实机成功率判断，不以训练 loss 或最后一步 checkpoint 单独判断。

## 最终判断

下一步采用“本机整理数据和实机评估，租用单卡 RTX 3090 Ubuntu 服务器训练”是当前最合理的方案。服务器本身不是当前唯一前置条件；在租机计费前应先完成六组数据的合并和静态验证，避免把租用时间消耗在数据格式排错上。
